**Locked design decisions:**
- Observation(Observation_ID BIGINT IDENTITY PK, Channel_ID INT NOT NULL FK→Channel,
  Timestamp DATETIME2(7) NOT NULL, DataType VARCHAR(10) NOT NULL)
- UNIQUE constraint on (Channel_ID, Timestamp, DataType) — one payload row per
  channel per timestamp per type
- Value table: drop Value_ID + Channel_ID + Timestamp; Observation_ID becomes PK
- Annotation: nullable Observation_ID FK added later (07-03)
- ProcessingLineage: unchanged

**Known constraint names from v1.0.0→v2.1.0 migration (confirmed):**
- FK_Value_Channel — FK on Value.Channel_ID → Channel
- PK on Value.Value_ID is named PK_Value (project convention; use dynamic lookup as safety net)

**Migration style (follow existing pattern):**
- Single transaction: BEGIN TRANSACTION at top, COMMIT at end of 07-03
- Schema guards at top (RAISERROR if wrong baseline)
- STEP N comments for each logical block
- GO separators after DDL statements
- SchemaVersion INSERT only in final plan (07-03)

  <action>
Append STEP 2 to the migration file. The Value table currently has:
  Value_ID (BIGINT IDENTITY PK), Channel_ID (INT nullable FK→Channel),
  Timestamp (DATETIME2(7) nullable), Value (FLOAT nullable)

Target: Observation_ID (BIGINT PK, FK→Observation), Value (FLOAT nullable)

Append in this exact order:

-- ============================================================
-- STEP 2: Data integrity check + backfill Observation from Value;
--         restructure Value as lean scalar payload
-- ============================================================

1. Pre-migration duplicate check — fail if any (Channel_ID, Timestamp) pair
   appears more than once in Value (would violate UQ_Observation_ChannelTimestampType):
   IF EXISTS (
       SELECT [Channel_ID], [Timestamp]
       FROM [dbo].[Value]
       WHERE [Channel_ID] IS NOT NULL AND [Timestamp] IS NOT NULL
       GROUP BY [Channel_ID], [Timestamp]
       HAVING COUNT(*) > 1
   )
       RAISERROR('Duplicate (Channel_ID, Timestamp) pairs in dbo.Value — deduplicate before migrating.', 16, 1);
   GO

2. Backfill Observation rows from Value (one per scalar row):
   INSERT INTO [dbo].[Observation] ([Channel_ID], [Timestamp], [DataType])
   SELECT [Channel_ID], [Timestamp], 'Scalar'
   FROM [dbo].[Value]
   WHERE [Channel_ID] IS NOT NULL AND [Timestamp] IS NOT NULL;
   GO

3. Add Observation_ID column to Value:
   ALTER TABLE [dbo].[Value] ADD [Observation_ID] BIGINT NULL;
   GO

4. Populate Observation_ID by joining back to Observation:
   UPDATE v
   SET v.[Observation_ID] = o.[Observation_ID]
   FROM [dbo].[Value] v
   JOIN [dbo].[Observation] o
       ON o.[Channel_ID] = v.[Channel_ID]
      AND o.[Timestamp]  = v.[Timestamp]
      AND o.[DataType]   = 'Scalar';
   GO

5. Make Observation_ID NOT NULL:
   ALTER TABLE [dbo].[Value] ALTER COLUMN [Observation_ID] BIGINT NOT NULL;
   GO

6. Drop FK_Value_Channel (blocks column drop):
   ALTER TABLE [dbo].[Value] DROP CONSTRAINT [FK_Value_Channel];
   GO

7. Drop PK on Value_ID (use dynamic name lookup for safety):
   DECLARE @pk NVARCHAR(200) = (
       SELECT name FROM sys.key_constraints
       WHERE parent_object_id = OBJECT_ID('dbo.Value') AND type = 'PK'
   );
   IF @pk IS NOT NULL
       EXEC('ALTER TABLE [dbo].[Value] DROP CONSTRAINT [' + @pk + ']');
   GO

8. Drop Value_ID (IDENTITY — safe: no other table FKs into Value.Value_ID):
   ALTER TABLE [dbo].[Value] DROP COLUMN [Value_ID];
   GO

9. Drop Channel_ID and Timestamp (now redundant, encoded in Observation):
   ALTER TABLE [dbo].[Value] DROP COLUMN [Channel_ID];
   ALTER TABLE [dbo].[Value] DROP COLUMN [Timestamp];
   GO

10. Add new PK on Observation_ID:
    ALTER TABLE [dbo].[Value]
        ADD CONSTRAINT [PK_Value] PRIMARY KEY ([Observation_ID]);
    GO

11. Add FK Observation_ID → Observation:
    ALTER TABLE [dbo].[Value]
        ADD CONSTRAINT [FK_Value_Observation]
        FOREIGN KEY ([Observation_ID]) REFERENCES [dbo].[Observation] ([Observation_ID]);
    GO

Do NOT add COMMIT — the transaction remains open for plans 07-02 and 07-03.
